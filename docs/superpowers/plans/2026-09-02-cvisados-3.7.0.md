# C-VISADOS 3.7.0 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implementar ingesta/vinculación segura, visor/lector Metro con fallback backend, separación Resoluciones/Gestión, cierre diario y UI compacta sobre C-VISADOS 3.6.4.

**Architecture:** Añadir helpers puros UMD para ingesta y gestión diaria, ampliar `workflow.js` con una frontera compatible de resolución concluida, y mantener `app.js`/`exporters.js` como integración de la UI existente. Guardar binarios opcionales en IndexedDB y proporcionar un servidor Node sin dependencias para scraping seguro del dominio Metro.

**Tech Stack:** HTML5, CSS, JavaScript ES2020/UMD, Node.js `node:test`, IndexedDB, Node.js HTTP/fetch sin dependencias externas.

**Spec:** `docs/superpowers/specs/2026-09-02-ingesta-resoluciones-gestion-design.md`

## Global Constraints
- Ningún campo nuevo es obligatorio; usar vacío, `null` o derivación compatible.
- No renombrar ni eliminar estados/campos persistidos de 3.6.4.
- No modificar machotes oficiales ni sus bytes.
- El scraper solo puede acceder por HTTPS a `metro.sarapiqui.go.cr`.
- La aplicación debe seguir operando como PWA estática aunque el backend no esté disponible.
